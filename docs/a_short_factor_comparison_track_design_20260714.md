# A-short 逐因素对照轨设计

日期：2026-07-14
状态：已实现 D1/D3 对照轨；本文件是执行与 Claude 审查的共同标准。D2、D4 另见各自切片。

## 1. 目标与边界

目标是让 A-short 每周把“原设计”和“只改一个因素的对照设计”分别跑出结果；数据积累后，系统对每个因素给出明确建议：采用该改变、保留原设计并舍弃对照，或继续积累。系统必须在建议产生后持续提醒用户。

- 仅限 A-short；不得混入 US-short、US-long 或 A-long。
- 对照轨永远是 comparison-only：不得改变当周正式 EGS、TopN、M6.7 操作建议、仓位、否决或任何自动下单行为。
- 系统可自动统计和建议；不得自动切换生产规则。切换必须另起 reviewed production-change slice，并由用户明确确认。
- 不得把历史回放或事后补写当作 forward 证据；只计决策当周冻结、随后自然结算的真实前瞻观察。

## 2. 本地结果位置

所有含股票名单、逐票收益、配对结果和用户决定的对照结果只写入：

```text
state/a_short/factor_comparison_private/
```

这是本地私密、gitignored 的唯一结果根目录。每个决策日使用一个独立子目录，目录名必须等于 `decision_date`：

```text
state/a_short/factor_comparison_private/
  20260714/
    manifest.json
    baseline_result.json
    factor_<factor_id>.json
    weekly_summary.json
  cumulative/
    factor_verdicts.json
    reminder.json
    user_decisions.json
```

- `baseline_result.json` 是原设计当周结果；每个 `factor_<factor_id>.json` 是一个因素的独立完整结果，不能只留一张汇总表。
- `manifest.json` 必须绑定同一 PIT 输入、候选池、成本模型、持有期、基线版本、对照版本和文件摘要。
- `weekly_summary.json` 只汇总本周；`factor_verdicts.json` 是累计裁决；`reminder.json` 是周报/终端应显示的提醒；`user_decisions.json` 只记录用户是否接受、拒绝或暂缓建议。
- 每周文件写入后不可静默改写；同日重跑只能在输入摘要完全相同的情况下幂等，否则必须失败。补写的历史文件必须标为非 forward，不能推进样本计数。

## 3. 每周必须产出的独立结果

每个活跃因素每周都必须产生一份独立成绩，而不是只有“选中的股票不同”。每份成绩至少包含：

1. 原设计与该因素对照的选股名单、共同名单和差异名单；
2. 同一基准、同一持有期、同一成本模型下的净收益与超额收益；
3. 配对周胜负、回撤、坏票率、尾部亏损、现金拖累、换手和成交/可执行性；
4. 数据完整性、价格/日历/PIT 状态和未结算原因；
5. 本周是否构成“有效差异周”。名单完全相同时，只能作诊断，不能计入因素效果样本。

比较单位是**决策周**，不是单只股票。这样不会把同一周高度相关的多只股票误当成很多独立样本。

## 4. 因素隔离规则

每个对照头必须在 `factor_registry` 中登记：`factor_id`、原规则、唯一改动、基线版本、适用范围、成本/持有期、启用日、冻结阈值和预期的生产变更。

- 一个对照头一次只能改一个因素；候选池、PIT 快照、选股名额、其他规则、成本和结算口径必须与基线相同。
- `factor_off` 胜出，表示原因素可能应移除或降权；替代规则胜出，表示该替代规则可能取代原规则；基线胜出，表示保留原规则并舍弃该对照头。
- 任何对照头若暗中同时改了两个因素、持有期、成本、候选池或仓位，结果无效，不能进入累计判断。
- 多个单因素都胜出时，不能直接一起改生产。必须建立一个“组合候选头”，再与原基线独立对照，确认因素之间没有互相抵消或放大风险。

## 5. 自动判断规则

不能只看胜率：很多次小赚也可能被一次大亏抹掉。每个因素的主判断必须是同周、扣成本后的配对净超额收益；胜率、回撤、坏票率、尾部亏损、现金拖累和换手是必须同时检查的保护指标。

实施前必须在 reviewed 的 schema/preset 中冻结每个因素的数值门槛，禁止看完结果再改线。以下状态是固定的：

| 状态 | 含义与动作 |
|---|---|
| `accumulating` | 少于 12 个有效差异周；只积累，不给采用/舍弃建议。 |
| `provisional_review_due` | 已有 12–23 个有效差异周；给“初审”提醒，但不能建议切换。 |
| `recommend_adopt_change` | 至少 24 个有效差异周、12 个非重叠 h10 块、跨至少两种独立状态，主收益、配对检验与风险保护指标均通过已冻结门槛；建议采用该单因素改变。 |
| `recommend_keep_baseline` | 样本足够且基线更好；建议保留原设计，并停止该对照头。 |
| `recommend_retire_head` | 累计至少 36 个有效差异周后，对照头仍呈经校正检验确认的持续结构性伤害；建议舍弃该对照头。 |
| `inconclusive` | 样本够但独立状态覆盖不足、功效不足、市场状态间冲突、主收益和风险指标相互矛盾，或数据不完整；不得采用或舍弃，只说明冲突原因。 |

`recommend_adopt_change` 至少要求：扣成本后的非重叠配对均值达到预先冻结的数值、配对块胜率达到预先冻结的数值、配对 sign-flip 检验经四头 Holm 校正后通过、95% 配对块置信区间下界为正，并且回撤、坏票率、尾部亏损、现金拖累和换手没有越过预先冻结的风险上限。缺一项即不能采用。

## 6. 自动提醒

每次周运行在新增结算结果后必须重算累计裁决，并在周报顶部和终端输出同一条明确提醒。提醒必须包含因素名、当前状态、有效差异周数、建议和下一步，例如：

```text
对照提醒：factor_x 有 26 个有效差异周，建议采用“关闭 X”；仍需用户确认，系统未改正式规则。
```

- `recommend_adopt_change`、`recommend_keep_baseline` 与 `recommend_retire_head` 必须每周重复提醒，直到 `user_decisions.json` 记录用户决定。
- `inconclusive` 必须说明是市场状态冲突、风险超线还是数据不完整；不得伪装成“没有问题”。
- 提醒程序失败、累计文件缺失、目录/日期/摘要不匹配时必须显式报错并标为未裁决，不能静默跳过。

## 7. 实施顺序

1. 先建 `factor_registry`、schema 和冻结 governance；未冻结门槛的因素不得开始计分。
2. 建每周基线与单因素头的私密捕获和完整结果文件。
3. 建前瞻收益结算器，严格绑定冻结名单、价格时钟、成本和持有期。
4. 建累计裁决器与 `factor_verdicts.json`。
5. 接入周报/终端的持续提醒。
6. 每次只增加一个因素头；单因素通过后，组合候选另起独立对照。

当前已冻结并接入的因素头：

- D1：`entry_ma_pullback`（MA10/MA20 附近回踩）与 `entry_range_pullback`（20 日区间下三分之一回踩）；突破规则仍使用原 V14.2，二者不与其他因素一起改。
- D3：`iv_step_down`（>90 不归零、继续缩仓）与 `iv_joint_stress`（>90 且 IV/HV 或环境压力同时成立才硬否决）。
- 冻结参数、三席虚拟对照仓位、T+1 开盘到 T+5/T+10/T+20 收盘、0.16% 双边成本、裁决阈值都以 `presets/a_short_factor_comparison_governance_20260714.json` 和 schema 为准；不能由运行结果反改。
- live 周跑在 M6.7 成功后把 PIT 归一化候选和一次 CSI300 独立状态摘要冻结到 private root；随后结算只消费既有 `forward_daily.pkl`，**结算阶段不额外抓数**。没有合格缓存时保留 `pending`，不能编造收益或推进样本。

## 8. Claude 审查标准

Claude 审查此轨道时必须逐项确认：

1. 每周基线和每个因素都有独立完整结果，且只写入本文件规定的私密目录；
2. 基线与对照使用同一 PIT 输入、候选池、名额、成本、持有期和结算时钟；
3. 每头只改变登记的一个因素；没有隐藏的多因素、仓位或候选池变化；
4. 历史回放、补写、未来价格、错日期、重复周、未结算周都不能推进 forward 样本；
5. 自动裁决严格读取冻结 governance，能覆盖采用、保留、舍弃和不确定四类结果；
6. 只凭胜率不得给采用建议；主收益和全部风险保护指标必须同时通过；
7. 提醒会持续出现，直到用户记录决定；提醒绝不自动改正式规则；
8. 因素组合在进入生产前已单独做组合对照；
9. 对照轨失败不会改变正式 A-short 输出，但会明确暴露失败，不能伪装为成功；
10. 测试必须覆盖 PIT/摘要绑定、单因素隔离、重复/补写拒绝、门槛边界、提醒持续、私密路径和无自动切换。

本对照轨已可运行；用户已授权其 live 周跑冻结与 cache-only 结算。它仍不授权改变生产规则或自动交易。

## 9. 2026-07-14 裁决修正：独立状态与统计门

生产 `market_regime` 目前可能长期为 `unknown -> 震荡期` 的 fail-closed 结果。它继续完全负责正式 M6.7 的风控；**不得**再作为本对照轨的状态覆盖门，也不得作为 `iv_joint_stress` 的实验性环境压力输入。否则“跨两种状态”的采用门永远走不到，`iv_joint_stress` 也可能从不与基线分歧。

本轨新增冻结的 `comparison_realized_regime`：每个 live 快照只为对照轨读取一次已授权的 CSI300 最近 21 个已结算收盘价，计算 20 日趋势和年化实现波动率，写入私密 manifest 的标签、截止日、指标和摘要。它的六个标签是 `trend_up/flat/down × vol_low/high`；数据不足、超出截止日或超过 7 日陈旧时写 `unavailable`。该状态只用于：

1. 要求采用建议至少覆盖两种**可用的独立状态**；
2. `iv_joint_stress` 的“环境压力”支路。下跌状态与横盘高波动属于压力；不可用时该头 fail-closed，不放宽 IV>90；
3. 裁决报告的分状态覆盖与稳定性说明。

它绝不写回生产 `market_regime`，不改变基线、M6.7、仓位、正式建议或交易。CSI300 查询失败仅令该周状态不可用；主周报与已冻结的其他比较结果继续运行。

主统计量改为 h10 的**非重叠配对净超额块**。每个块由互不重叠的基线/因素持有期构成，避免周频 h10 窗口把同一行情重复当作独立样本。采用或舍弃都必须同时满足：

- 冻结的有效差异周数与非重叠块数；
- 配对均值、95% 配对块 bootstrap 置信区间和以配对差量级（|均值|）为对象的**双侧** sign-flip permutation p 值（实现 `_sign_flip_two_sided_pvalue`；方向由配对均值与置信区间给出，符号检验仅作单侧稳健性展示）；
- 对全部四个头同时做 Holm-Bonferroni 校正后 `p <= 0.05`；符号检验只作稳健性展示，不再单独决定采用；
- 原有回撤、坏票率等风险保护线，以及采用时的两种独立状态覆盖。

报告还必须给出分歧频率、前后半段的均值和功效诊断（按当前块波动估算检测 0.25% 周度配对优势所需的块数）。因此“24 周”是最早可审查点，不是必然足够的证据。36 周仍未证明优势只能是 `inconclusive`；只有校正后显著、且方向明确的持续伤害，才能 `recommend_retire_head`。没有证据不得被当作坏因素自动舍弃。

四个单因素头仍保持冻结。组合头仍须在单因素有 `recommend_adopt_change` 后另起独立预注册切片，并且必须同时胜过基线和当前最强单因素；本次不实现组合头。

Claude 后续审查还必须验证：独立状态不回流生产、不可用状态 fail-closed、D3 只替换已登记的压力输入、非重叠块与 h10 退出日不交叠、Holm 校正覆盖四头、36 周“无证据”不触发舍弃，以及新增的状态/统计/补写/私密路径边界测试。
