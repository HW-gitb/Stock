# A Short Rank Backtest Outputs

Generated by `runners/backtest_rank.py`.

## Layout

- `generated/YYYYMMDD/`: isolated candidate pools produced for backtest only (never overwrites `result/a_short/YYYYMMDD/`).
- `cache/forward_daily.pkl`: dedicated Tushare daily + adj_factor + benchmark cache covering the forward window.
- `rank_samples.csv`: one row per candidate per as-of date with five return variants (see below).
- `summary_by_window.csv`: overall stats per (window, variant).
- `factor_group_stats.csv`: rank / score / data-quality / overheat / low-base-growth group stats (variant=t1_net by default).
- `rule6_stats.csv`: Rule 6 triggered / not-triggered group stats.
- `backtest_report.json`: machine-readable manifest, mode, settings, limitations.

## Return variants

| variant | meaning |
|---|---|
| `close` | qfq close-to-close. No T+1, no cost. Reference only. |
| `t1` | qfq T+1 open entry to close of T+1+W. Gross. |
| `t1_net` | `t1` minus round-trip cost (default 0.16%). |
| `excess_csi300` | `t1` minus CSI300 same-window return. |
| `excess_csi1000` | `t1` minus CSI1000 same-window return. |

## Modes

| `--mode` | When to use |
|---|---|
| `smoke` (default) | System testing. Allows `--reuse-l3-cache` and `--include-immature`. Report flags `engineering_smoke: true`. |
| `production` | Serious backtest. Refuses both shortcuts. Forces L3 refresh and mature as-of dates. |

## Known limitations

**Read this before publishing any results.**

1. **L3 concept data is today's snapshot, not point-in-time.** Tushare's `pro.concept` / `pro.concept_detail` does not expose history. Cross-year or hot-theme backtests therefore leak future information into `cat_score`. Acceptable for short windows (1-2 months), unsafe for serious historical backtest. Fix would require maintaining local L3 snapshots per as-of date.
2. **Financial data revisions.** Tushare returns the latest revision of each quarter rather than the originally-disclosed version, even with `ann_date <= as_of` filtering applied. API limitation.
3. **Sample correlation.** Adjacent as-of dates with `--freq weekly` and `--windows 20` have overlapping forward windows -> variance is underestimated. Prefer `--freq monthly` for `max_window=20`, or use `--dedup-mode by_ts_code`.
4. **Immature as-of dates** (those with fewer than `max_window + 1` trading days of future data) are skipped by default. Use `--include-immature` only for smoke testing.

Pending return windows are expected until enough future trading days exist between as-of and today.
